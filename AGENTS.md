# Правила работы с wallet-ledger-service

## Контекст проекта

- Java 25, Spring Boot, Gradle Wrapper, gRPC и Protocol Buffers.
- PostgreSQL хранит балансы, ledger и transactional outbox; Redis используется для блокировок, RabbitMQ — для событий.
- Перед изменениями прочитай относящиеся к задаче код, тесты и разделы README.md.
- Если есть документация требований, прочитай относящиеся к задаче документы. Не считай отсутствующие документы существующими.
- При противоречии требований и реализации обозначь расхождение. Текущие явные указания пользователя имеют приоритет.
- README.md пока содержит устаревшее описание retry Redis-блокировки: повторные попытки удалены. Не восстанавливай их на основании README.

## Локальные навыки

- Навыки проекта размещаются в `.agents/skills/<имя>/SKILL.md`.
- Перед выполнением задачи проверь доступные проектные навыки и их описания.
- Если задача соответствует описанию навыка, прочитай его SKILL.md и примени инструкции без отдельного напоминания пользователя.
- При явном указании навыка пользователем обязательно прочитай его. Если он отсутствует, сообщи об этом.
- Не загружай все вспомогательные материалы навыков заранее: читай только необходимые для задачи.

## Изменения кода

- Сохраняй структуру пакетов и стиль окружающего кода. Делай изменения в пределах задачи.
- Не перезаписывай чужие незакоммиченные изменения.
- При изменении поведения проверь связанные настройки, тесты и документацию.
- Сохраняй идемпотентность операций, неизменяемость ledger и атомарность записи баланса, ledger и outbox, если задача явно не меняет эти требования.
- Проверяй границы транзакций и конкурентный доступ при изменении финансовых операций.
- Сгенерированные protobuf/gRPC-классы не редактируй вручную: меняй исходные схемы и запускай генерацию.
- Для изменения схемы БД добавляй новую Flyway-миграцию; не переписывай уже применённые миграции.

## Проверка изменений

- Используй Gradle Wrapper из проекта.
- В PowerShell запуск отдельного тестового класса: `.\gradlew.bat test --tests <полное.имя.Класса>`.
- Запуск всех тестов: `.\gradlew.bat test`.
- Для тестов с Testcontainers нужен работающий Docker. Если он недоступен, явно укажи, какие проверки не выполнены.
- Для изменения поведения запускай соответствующие тесты; расширяй проверку при изменениях, затрагивающих несколько компонентов.
- Для правок только документации достаточно проверить содержание и diff, без запуска приложения и тестов.
- В отчёте укажи результат проверок и реальные ограничения; не называй непройденную проверку успешной.

## Доступ и Git

- При работе над проектом ограничивай файловые обращения проектом, необходимыми зависимостями и служебными каталогами инструментов.
- Не просматривай личные документы и другие проекты без явного запроса пользователя.
- Соблюдай действующие разрешения среды; не обходи отказ песочницы через MCP IDEA или другой инструмент.
- Эти правила являются инструкциями агенту и не заменяют техническую изоляцию файловой системы.
- Коммит и push выполняй по запросу пользователя. Не применяй force push и не переписывай историю без явного указания.
